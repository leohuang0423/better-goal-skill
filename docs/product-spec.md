# 有效成交增长 Agent — 开发 Spec（v0.1）

> 一句话定位：每天自动发现商家最该做的 ≤3 件经营动作，估算收益/风险，生成**可审批任务包**，执行后盯结果，并用真实数据证明"今天帮你多赚了什么、少亏了什么"。
>
> 第一版（MVP）只做 **退货 / 体验分止损 Agent**，垂直打透**服饰类目**。

---

## 0. 设计原则（不可妥协）

1. **闭环 > 对话**。产品主体是一个每天自动运行的 Agent 循环，对话框只是审批与追问入口。
2. **延迟事实优先**。当天 ROI 不算数；以 7/14 日退货窗口闭合后的**真实利润**为准。
3. **数字不许 LLM 编**。LLM 负责"做什么 + 为什么"，收益/风险金额由确定性算法计算。
4. **一切可回滚 + 留快照**。任何会改变经营状态的动作必须可逆、可审计。
5. **默认人审**。MVP 阶段所有写操作都走"建议 → 人工一键执行"，不做全自动。
6. **可验证才发布**。每个动作必须挂复盘任务；预测命中率是核心质量指标。

## 2. 模块规格

### 2.1 数据感知层 (Sense)

**目标**：把碎片数据汇成可推理的「实体时间线」。

**核心数据源**

| 数据源 | 接口 | 关键字段 |
|---|---|---|
| 抖店-订单 | `/order/list` `/order/detail` | 订单状态、SKU、金额、下单时间 |
| 抖店-售后 | `/afterSale/list` | 退款/退货原因、申请时间、闭合时间、金额 |
| 抖店-商品 | `/product/detail` | 标题、主图、详情页、尺码表、价格 |
| 抖店-评价 | `/comment/list` | 评分、文本、关联 SKU |
| 巨量千川 | 投放报表 / 计划 API | 计划 ID、消耗、ROI、点击率、转化率 |
| 罗盘 | 导出 / 抓取 | 体验分、品退率、物流品退率、差评率、投诉率 |
| 客服 IM | 会话日志 | 售前承诺、纠纷关键词 |

**实体时间线模型**

```jsonc
// entity_timeline 表（每个实体一条时间轴）
{
  "entity_type": "sku | ad_plan | influencer | video",
  "entity_id": "1234567",
  "events": [
    { "ts": "2026-06-20T10:00", "type": "ad_change", "payload": {...} },
    { "ts": "2026-06-22T14:30", "type": "refund", "payload": { "reason": "尺码偏小", "amount": 89 } }
  ]
}
```

**延迟事实回填**：每笔订单创建一个 7d / 14d 的"利润结算任务"，窗口闭合后回填真实退货金额，重算单 SKU / 单计划真实利润。**所有下游决策只读真实利润字段**。

---

### 2.2 归因引擎 (Diagnose)

**输入**：问题 SKU 的时间线 + 退款留言 + 差评文本 + 客服会话。

**输出**：结构化归因。

```jsonc
{
  "sku_id": "1234567",
  "issue": "high_return_rate",
  "metrics": { "return_rate_7d": 0.34, "industry_p50": 0.18 },
  "root_causes": [
    { "cause": "尺码偏小", "evidence_ratio": 0.62, "evidence": ["退款留言x18","差评x7"] },
    { "cause": "物流慢",   "evidence_ratio": 0.21, "evidence": ["退款留言x6"] }
  ],
  "confidence": 0.81
}
```

**分工**：LLM 负责从非结构化文本抽取并归类原因（少量标注 + few-shot）；占比、阈值对比由规则计算。归因原因走**封闭枚举**（尺码/材质/色差/物流/客服承诺/质量/价格/其他），便于评测和沉淀。

---

### 2.3 决策 / 编排层 (Decide + Plan)

**目标**：每天产出 ≤3 个动作，封装成审批卡。

**审批卡 Schema**（产品契约，前后端 + 评测共用）

```jsonc
{
  "action_id": "act_20260624_001",
  "card_type": "止损 | 放大 | 修复",
  "title": "暂停 A 商品 2 个千川计划",
  "reason": "7日退货后利润为负，退款原因集中在'尺码偏小'(62%)",
  "linked_actions": [
    { "type": "edit_detail_page", "target": "sku_1234567", "change": "尺码表+大一码提示" },
    { "type": "edit_cs_script",   "target": "presale",     "change": "增加尺码确认话术" },
    { "type": "pause_ad_plan",    "target": ["plan_88","plan_91"] },
    { "type": "shift_budget",     "from": "sku_A", "to": "sku_B", "ratio": 0.3 }
  ],
  "impact_estimate": {
    "metric": "7d_profit",
    "delta_min": 4000, "delta_max": 8000, "currency": "CNY",
    "secondary": ["降低品退风险", "保住体验分"]
  },
  "risk": ["短期 GMV 可能下降 5-10%"],
  "requires_approval": true,
  "rollback": { "supported": true, "snapshot_id": "snap_001" },
  "confidence": 0.76
}
```

**收益/风险估算（确定性，禁止 LLM 生成数字）**
- `少亏` = 问题 SKU 当前 7d 亏损率 × 受影响预算 × 预期改善系数（系数来自历史同类动作的回填效果，冷启动用保守先验）。
- 估算永远给**区间**，并在卡片标注口径。模型只能引用引擎算出的数字，不能新造。

---

### 2.4 执行层 (Act)

**权限三档**

| 档位 | 动作举例 | 默认行为 |
|---|---|---|
| L0 只读 | 给建议 | 直接展示 |
| L1 需审批 | 停计划、改详情页、转预算、暂停达人 | 一键执行，执行前存快照 |
| L2 白名单自动 | 低风险可逆动作（如客服话术草稿） | 商家预授权后自动，仍记账 |

**执行前**：写 `snapshot`（改前状态）。**执行后**：写 `action_ledger`（谁、何时、改了什么、快照 ID）。**回滚**：一键从快照还原。

---

### 2.5 盯盘 / 复盘层 (Verify)

每个已执行动作挂 3d / 7d / 14d 观察任务，回填后产出复盘卡：

```jsonc
{
  "action_id": "act_20260624_001",
  "predicted": { "delta_min": 4000, "delta_max": 8000 },
  "actual": { "delta": 5200, "window": "7d" },
  "hit": true,           // actual 是否落在预测区间
  "verdict": "退货率 0.34 → 0.19，体验分未下滑，实际少亏 5200 元"
}
```

`hit` 命中率是产品核心质量指标，也直接喂回估算系数（闭环学习）。

---

### 2.6 沉淀层 (Learn / 错题本)

把 `(类目, 商品特征, 归因原因) → 有效动作 + 实际效果` 沉淀为商家私有知识（向量库 + 结构化规则）。新品上架前做相似检索，命中则预警："同类商品历史尺码退货高，建议上架即配大一码提示"。

## 3. Agent 主循环（伪代码）

```python
def daily_run(shop_id):
    timelines = sense.refresh(shop_id)          # 拉数据 + 回填延迟事实
    problems  = diagnose.find_issues(timelines) # 退货/差评/体验分异常 SKU
    problems  = rank_by_loss(problems)[:TOP_N]  # 按"在亏的钱"排序

    cards = []
    for p in problems:
        attribution = diagnose.attribute(p)     # LLM 抽取 + 规则归类
        plan        = decide.make_plan(p, attribution)  # LLM 规划动作
        plan.impact = estimator.compute(p, plan)        # 确定性算金额(覆盖LLM)
        cards.append(plan.to_approval_card())

    cards = cards[:3]                            # 硬上限 3 张
    push_to_console(shop_id, cards)              # 等人审批

    for act in get_approved_actions(shop_id):
        snap = act.snapshot(); act.execute()     # 留快照后执行
        verify.schedule(act, windows=[3,7,14])   # 挂盯盘任务

    for done in verify.due_reviews(shop_id):     # 回填复盘
        result = verify.evaluate(done)
        estimator.update_coefficient(result)     # 命中率喂回模型
        learn.record(done, result)               # 写错题本
```

## 4. MVP 范围（务必克制）

| 砍掉（v0.1 不做） | 保留 |
|---|---|
| 爆品放大 / 达人流水线 / 内容生成 | 退货归因 + 止损动作包 + 审批 + 7日复盘 |
| L2 全自动执行 | 全部 L0/L1（建议 → 人工一键执行） |
| 全类目 | 仅服饰 |
| 多账号矩阵 | 单店 |

**完成标准**：单店跑通"发现亏损 SKU → 归因 → 出止损审批卡 → 执行 → 7日复盘出真实少亏金额"全链，且复盘命中率达标（见 §5）。

---

## 5. 验证指标（PLF 信号）

| 指标 | 定义 | v0.1 目标 |
|---|---|---|
| 审批卡采纳率 | 被一键执行的卡 / 推送的卡 | > 40% |
| 预测命中率 | 复盘 actual 落入预测区间 / 已复盘动作 | > 60% |
| 主动打开率 | 商家主动打开动作台天数 / 自然日 | > 50% |
| 归因准确率 | 见评测 Benchmark §见 eval/ | > 80% |
| 误伤率 | 执行后核心指标反而恶化的动作占比 | < 10% |

---

## 6. 里程碑

- **M1（2 周）** 数据感知层 + 实体时间线 + 延迟事实回填（服饰单店打通）。
- **M2（2 周）** 归因引擎 + 评测集跑到 80% 归因准确率。
- **M3（2 周）** 决策层 + 审批卡 + 估算引擎 + 动作台前端。
- **M4（2 周）** 执行(L1) + 快照/回滚 + 盯盘复盘闭环。
- **M5（持续）** 错题本沉淀 + 估算系数闭环学习 + 灰度真实商家。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 数据接口拿不全（罗盘无开放 API） | 优先用抖店+千川官方 API；罗盘走授权导出，体验分用规则近似 |
| LLM 编造金额 / 归因 | 数字走确定性引擎；归因走封闭枚举 + 证据引用；上线前过 Benchmark |
| 商家不敢给写权限 | MVP 全程人审 + 快照可回滚 + 动作账本透明 |
| 误伤好计划 | 估算区间保守 + 误伤率监控 + 一键回滚 |
| 平台规则变动 | 规则配置化，集中维护体验分/考核口径 |
